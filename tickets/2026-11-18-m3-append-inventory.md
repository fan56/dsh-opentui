### 1.2 `systemPrompt.section` 宿主 API 真实签名 / order / scope / 去重

宿主包：`@deepseek-ai/dsh-system-prompt@0.2.2-rc.3`（pnpm 路径 `node_modules/.pnpm/@deepseek-ai+dsh-system-prompt@0.2.2-rc.3_.../node_modules/@deepseek-ai/dsh-system-prompt`）。以下行号均指该包 `src/index.ts`。

- 签名：`section(section: PromptSection): () => void`（`:485`）。`PromptSection` = `{ name: string; order: number; text: string | (ctx: AssembleContext) => string; interpolate?: boolean; complete?: boolean }`（`:53-72`）。`order` 非有限数抛 `TypeError`（`:486-488`）。
- 注册方式：`this.layers.effect(this.ctx, layer => layer.sections.insert(name, section), { label: 'systemPrompt.section()' })`（`:489-493`）——**注册在「调用方 ctx 的 scope」**，返回 Cordis disposer，注册/销毁都 emit `system-prompt/change`。
- `order` 语义：升序拼接，相同 order 用 **code-unit 名称序**（`:57-58`，`comparePromptSections` `:263`）。**`order: 200` 不是任何具名常量**：`SECTION_ORDERS`（`:136-166`）从 `HARNESS_IDENTITY:-1000`、`DEPLOYMENT_PERSONA_PREFIX:0`、`PLAN_POLICY:500` 一直到 `DEPLOYMENT_PERSONA_SUFFIX:10200`，无 200；`getSectionOrder(name)`（`:501-503`）只接受 `keyof SECTION_ORDERS`。所以契约里的 `order: 200` 只能是**字面量**，不能写 `getSectionOrder(...)`。
- scope 归属 = `agentCtx`（agent scope）：PromptLayer 的 duplicate 报错明确写 "for a per-agent override, register through that agent's `agent.ctx` instead"（`:414-417`）；per-agent 注册的入口是 `AgentOptions.setup?: AgentSetup`（`dsh-agent/src/index.ts:120` / `ResumeAgentOptions.setup` `:143`），回调签名 `(agentCtx: Context, agent: Agent) => ...`（`:54-57`）。bridge 在宿主进程内直调 `agents.create/resume`，可在 options 里传 `setup` 回调拿到 `agentCtx`（**UNKNOWN**：传函数跨 stdio 边界是否可达——bridge 进程内直调故理论可行，但需真机烟测确认）。
- 去重机制有两层：
  1. **API 层**：同名 section 在同一 layer 内重复 `insert` 抛错；**scoped section 覆盖（shadow）global 同名 section**而非叠加（`:479-481`）。共享常量 `PERSONA_PREFIX_SECTION = 'deployment:persona-prefix'`（`:197`）/ `PERSONA_SUFFIX_SECTION = 'deployment:persona-suffix'`（`:200`）就是让 preset 与 deployment 用同一个 name 来实现替换。
  2. **契约层（M3 要实现）**：ADR-0010「防重」——会话记录里 preset 已含 append 合成 id 时 section 文本函数返回空串（`docs/adr/0010-session-seam-lifecycle-contract.md:142`）。
- 「禁 global」= 不要注册到 root ctx，要注册到 agent scope；这样与 tui-pi 共装时靠 scope shadow + order tie-break，而不是靠注册先后偶然行为（ADR-0009 `:69`、ADR-0010 `:135-137`）。
